# 多图库路径设计（修订：统一命名空间 + /@img 跨库）

> 修订依据：`/@img` 应包含附加库；附加库统一挂在一个命名空间下，而不是散落的 `/2/`、`/3/`。

## URL 形状

| 功能 | 主库 | 附加库（统一前缀 `/lib/<库名>/`） |
| --- | --- | --- |
| 分类随机 | `/{分类}` | `/lib/{库名}/{分类}` |
| 图片 | `/pic/{分类}/{文件}` | `/lib/{库名}/pic/{分类}/{文件}` |
| JSON | `/json?{分类}` | `/lib/{库名}/json?{分类}` |
| 图库 | `/img?category=` | `/lib/{库名}/img?category=` |
| 单库随机 | `/@img` 见下 | `/lib/{库名}/@img`（仅该库） |

### `/@img` 语义（本次修订）

`/@img` = **跨全部库**（主库 + 所有附加库）加权随机：

```
分类权重 = sqrt(该分类图片数) + ECY_AGG_FLOOR
选择分类 → 分类内按图片等概率取一张
```

也就是说：**新增一个大库会自动获得更大份额**，这正是「加入新图库后它就该被抽到」的语义。

如果只需要主库，用 `/@img?lib=main`；只要某个附加库，用 `/lib/{库名}/@img`。

## 为什么用「统一前缀 + 库名」而不是 `/2/`、`/3/`

| | `/2/`、`/3/` | `/lib/<库名>/` |
| --- | --- | --- |
| 可读性 | 差（数字无意义） | 好（库名自解释） |
| 稳定性 | 槽位号不能复用，删除后留下空洞 | 库名即标识，删了再加同名仍指向同一逻辑库 |
| 分享链接 | `/2/pic/…` 别人看不懂 | `/lib/网盘/pic/…` 自解释 |
| 上限 | 需要管理号段 | 无 |

约束：库名只能含 `[A-Za-z0-9_-]` 与中文，不得含 `/`，且全局唯一。

## 内部表示

```go
type Root struct {
    Name   string // 主库为空串；附加库如 "网盘"
    Path   string // 真实目录，可在任意挂载点
    IsMain bool
}

// 分类在内部统一带命名空间前缀，用不可见分隔符 \x01 隔开：
//   主库：  "风景/2024"
//   附加库："\x01网盘\x01风景/2024"
```

用 `\x01` 而不是可见前缀，避免与真实目录名（可能就叫 `lib/xxx`）冲突。

## 数据与配置

- `ECY_DATA_DIR`：主库，URL 与行为完全不变
- `data/roots.json`：附加库列表 `[{name, path, enabled}]`，后台增删改
- 快照 / `index.bin`：分类名已带命名空间前缀，**格式无需改动**

## 改动面

| 层 | 改动 |
| --- | --- |
| `config` | 主库来自 `ECY_DATA_DIR`；附加库来自 `roots.json` |
| `store.scan` | 遍历 roots，`scanDir` 带 base 路径与命名空间前缀 |
| `store` 管理接口 | `absPath(cat, file)` 按前缀解析真实路径 |
| `server` 路由 | 识别 `/lib/<库名>/` → 剥离后复用现有 handler |
| `server` 统计 | `Categories()` / `Counts()` 返回全库；新增按库过滤 |
| 后台 | 「图库目录」页：增删改附加库，显示各库分类数/图片数/可用状态 |

## 验收

1. 单库：所有 URL 与 `/@img` 分布与现在一致（现有测试兜底）
2. 两库：`/lib/网盘/pic/风景/x.jpg` 能取到第 2 库文件；主库 URL 不受影响
3. `/@img` 覆盖两库，且大库被抽中的比例符合 `sqrt(n)+floor` 预期（用 `TestAggregateDistributionLocked` 同款统计法验证）
4. `/lib/网盘/@img` 只出第 2 库的图
5. 两库同名分类（都叫「风景」）互不干扰
6. 删除附加库 → 其 URL 全 404，主库与 `/@img` 正常

## 风险

- 某附加库挂载失败（U 盘未插）不能让整个服务崩：该库标记不可用，其余正常
- 缩略图缓存 key 必须带命名空间前缀，否则同名分类互相覆盖
- `/@img` 从「主库」变成「全库」是**行为变更**：上线后随机分布会变，需在发布说明里写清楚
