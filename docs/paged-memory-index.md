# 内存模式 + 索引分页（替代 compact 的路线）

> 决策：**不采用 compact 模式**（丢弃聚合预建、Verify、快照语义）。
> 改为：保留内存模式的全部语义，把「条目驻留」换成分页换入换出。

## 目标

| 指标 | 现状（内存模式，100 万张） | 目标 |
| --- | --- | --- |
| 常驻内存 | 306 MB（每条 321B） | ≤ 120 MB |
| 聚合 | 预建，O(1) | 预建，O(1)（不变） |
| Verify | 每请求 stat | 不变 |
| 快照 | JSON，热启动秒开 | 不变 |
| 随机 / 分页顺序 | 名字序 | 不变（关键：compact 曾在这里出错） |

## 核心：把「分类条目数组」变成可换页的分段

现在每个分类的条目是 `[]fileEntry`（每条约 321B，含两个字符串头）。
改为：

1. **磁盘段**：`internal/index` 已经是按分类分组的定长记录（28B/条）+ 路径 arena，
   mmap 打开即可随机取任意一条 —— 分页的底座已存在。
2. **内存页**：每个分类在内存里只保留「位置数组 + 名字偏移」的可选缓存，
   按 LRU 限量（例如 200 MB 上限、或 N 个分类）。
3. **热分类常驻**：访问频率高的分类整体驻留，冷分类按需换入。

## 分页粒度选择的三种方案

| 方案 | 粒度 | 换入代价 | 适用 |
| --- | --- | --- | --- |
| A | 单条记录 | 一次 mmap 读（~100ns） | 不需要，太细 |
| **B** | **分类**（500 条/页） | 读一条记录 × N（可预取） | **推荐**：与随机访问模式一致 |
| C | 目录子树 | 大，换入慢 | 深层嵌套 |

选 B：随机访问天然是「先选分类，再选条目」，一个分类换入即可服务一整批请求。

## 聚合怎么保持 O(1)

内存模式的 `aggKids` 持有 `[]fileEntry` 切片——这是内存大户，也是 compact 放弃预建的原因。
改为**位置索引**：

```go
type aggUnit struct {
    cat    uint32   // 分类 id
    offset uint32   // 该分类在页内的起始位置
    count  uint32   // 条目数（权重用）
}
```

聚合桶只存 `[]aggUnit`（每分类一个，几十字节），随机时：

1. 按 `sqrt(count)+floor` 权重选一个 unit（与现在完全一致）
2. 从对应分类的**页**里取第 k 条（页未驻留则 mmap 读一条）

这样聚合从「每图片 321B」降到「每分类 ~16B」，100 万张 / 2000 分类 = **32KB**。

## 需要改的地方（按顺序）

| # | 改动 | 风险 |
| --- | --- | --- |
| 1 | `aggKids` 改为 `[]aggUnit`，随机时按 unit → 分类 → 页取行 | 中（聚合是核心路径） |
| 2 | `categorySet` 改为「页描述符」（位置数组 + 名字序），热分类物化成 `[]fileEntry` 供 Verify 用 | 中 |
| 3 | 扫描结果的写入：扫描仍建全量 `fileEntry`，但只保留「页缓存上限」内的分类，其余压缩成位置数组 | 高（扫描期峰值） |
| 4 | 分页缓存上限可配（`ECY_INDEX_PAGE_MB`，默认 200） | 低 |

## 为什么这条路比 compact 好

| | compact | 内存分页 |
| --- | --- | --- |
| 聚合 | 现算 O(分类数) | 预建 O(1) |
| 外部删文件 | 最长 10 分钟才 404 | 立即 404（Verify 不变） |
| 快照 | 不写，索引丢了要重扫 | 保留，热启动秒开 |
| 名字序 | 需要重排一次（曾出错） | 原样保留 |
| 内存 | 121 MB（100 万张） | 目标 ≤120 MB（同等），但语义完整 |

## 已知前置条件

- `internal/index` 的 `size` 是 uint32，>4GiB 会被压平 —— 这条路要用它存权威数据，**必须先修成 uint64**
- 页缓存要能按字节计量（不是按分类个数），否则大小分类混在一起会失真
